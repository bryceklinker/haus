# Plan: Upgrade to .NET 10 (issue #11)

Acceptance criteria: https://github.com/bryceklinker/haus/issues/11#issuecomment-5018635677

Delivered as **one PR** against `main`. Four tracks fan out from a single
framework baseline increment; within a track, increments are sequential;
across tracks (B, C, D), increments are independent (disjoint files) and can
run in parallel once increment 1 has landed.

Note on TDD shape: increments 1–3 and the FluentAssertions increments (13–22)
are mechanical/infrastructure changes with no new behavior — there is no
meaningful red before green. Their "test" is the existing test suite staying
green (and, for FluentAssertions, staying semantically identical). Increments
4–12 (the MediatR replacement) are genuine new production code and get full
strict-TDD red-green-refactor treatment.

## Track C — Replace MediatR with an in-house dispatcher (depends: 1)

All new files live in `src/Haus.Cqrs` (new internals) and a new
`tests/Haus.Cqrs.Tests` project until increment 12, so increments 4–11 don't
touch any file MediatR consumers or Tracks B/D touch.

4. **[depends: 1]** Command dispatch: sending an `ICommand` with no result
   invokes its single registered handler.
   - files: `tests/Haus.Cqrs.Tests/**` (new project, first test), `src/Haus.Cqrs/**` (new dispatcher)
5. **[depends: 4]** Command dispatch with zero handlers registered throws a
   clear error.
6. **[depends: 4]** Command dispatch with multiple handlers registered throws
   a clear error.
7. **[depends: 4]** Command dispatch with result: `ICommand<TResult>` returns
   the handler's result (zero/multiple-handler cases mirror 5/6).
8. **[depends: 4]** Query dispatch: `IQuery<TResult>` invokes its single
   handler and returns the result; zero/multiple handlers throw.
9. **[depends: 4]** Event publish: `IEvent` invokes all zero-to-many
   registered handlers.
10. **[depends: 9]** Domain event enqueue/flush: `Enqueue` batches domain
    events; `FlushAsync` dispatches each to all registered handlers in
    enqueue order, then clears the queue.
11. **[depends: 5,6,7,8,9,10]** Assembly-scanning DI registration:
    `AddHausCqrs(assemblies)` discovers and registers all
    `ICommandHandler`/`IQueryHandler`/`IEventHandler`/`IDomainEventHandler`
    implementations from the given assemblies.
12. **[depends: 11]** Swap `CommandBus`/`QueryBus`/`EventBus`/`DomainEventBus`/
    `ServiceCollectionExtensions` to the new dispatcher (wiring the existing
    `Logging*Bus` decorators exactly as today); remove the MediatR package
    reference from `Haus.Cqrs.csproj`.
    - files: `src/Haus.Cqrs/Commands/CommandBus.cs`,
      `src/Haus.Cqrs/Queries/QueryBus.cs`, `src/Haus.Cqrs/Events/EventBus.cs`,
      `src/Haus.Cqrs/DomainEvents/DomainEventBus.cs`,
      `src/Haus.Cqrs/ServiceCollectionExtensions.cs`, `src/Haus.Cqrs/Haus.Cqrs.csproj`
    - criteria: MediatR removal (both bullets)
    - verify: full solution build + full existing unit-test suite green —
      this is the regression proof that all ~35 consumer handlers
      (`ICommand`/`IQuery`/`IEvent`/`IDomainEvent` implementations elsewhere)
      still work unchanged, since they never referenced MediatR directly
